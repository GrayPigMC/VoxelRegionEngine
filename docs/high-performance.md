# 批量执行与一致性契约

算法库和 Forge 适配器分开发布。几何、掩码、传播索引不访问 Minecraft 世界；Forge 适配器负责取得世界数据、检查权限和提交。测试 mod 只提供物品与命令。GTLCore 的源码同步、嵌入和真实宿主观察器见 [对接文档](gtlcore-integration.md)。

## 从中心推进

新任务默认以整个区块为提交单位，从爆心区块向外推进。优先队列按爆心到区块水平包围盒的距离排序，每个区块只访问一次；不先构建整个半径范围的区块列表。游标可持久化恢复。

`AS_FAST_AS_POSSIBLE` 仍按 Region 局部性排序。两种模式的几何结果相同，均准备整个区块再在一次服务端调用内提交。准备可跨 tick；已经准备但尚未提交的地形保持不变。旧任务持久化的球壳格式保持原样，不能用新规则解释旧进度；`shell_width_blocks` 只影响该旧格式。

新 API 和测试命令默认 `generate=true`：按有界窗口读取或生成整个请求范围。显式 `generate=false` 仍读取已有存档中的未加载 FULL 区块，仅排除需要生成的区块。旧格式任务保留原先“只处理已加载区块”的含义。状态显示排除数量；范围受限的完成不等于整个球体都已清除。

## 提交路径

完整覆盖的静态区段先检查 Palette、精确非空气计数、权限、修订号和宿主观察器支持。能证明安全时，一次替换状态容器，保留生物群系；同一区块内可批量提交多个区段。它不执行 4096 次 `setBlock`。

边界使用连续 Y 行段生成局部掩码。混有基岩等受保护状态的区段在离线 Palette 中构造替换，不再因此退回逐个地形 `setBlock`。普通原版静态地形按精确方块类型证明；方块实体、特殊回调或未知状态保留在原生处理掩码，批量交换之后重新检查其当前状态和权限，再执行必要回调。领地禁止的区块和完整阴影直接跳过。相关宿主观察器必须通过聚合通知契约；不再因为安装了无关模组而全局关闭批量路径。

批量写入后一次重建四种 FULL 高度图和天光源列，只清理实际删除位置的定时刻，并请求光照更新。外部光照策略必须提供真实完成 future，保存和发包以此为前置条件，再等待原生队列的修订一致性屏障。不得伪造 `isLightCorrect`，也不得借用生成光照票据作为普通重照明完成证明。

整区块执行先完成 Palette 替换和剩余原生删除，再用最终区块尝试 `ClearedChunkLightBatch.afterWholeChunkMutation`。旧计划的原生余项数量不能代表最终还留有什么。提前退出或原生回调抛错时，延迟光照依赖必须转入真实原生修复；不能遗留永不完成的保存 future。

快速光照当前证明整个世界高度内只剩空气或不发光、不透光的状态。捕获实际边界之前先等待周围九个区块的原生旧光照工作；等待期间修改使证明失效时，最多重新获取一次区块身份与修订号，再等待新的屏障。开始捕获后不能靠重置修订号接受旧快照。水、发光残留、邻块未加载或再次失效仍走原生路径。有限枚举的 `fallbackReasonCounts()` 和 `preCaptureRefreshes()` 用于区分适用性、容量和修订失效，不能用安装算法存在来推断生产命中率。

四个侧面的光照捕获按邻区块、区段读取原生 **visible** 光层，每层复制一次后直接读取局部 nibble；不使用会优先返回 queued、尚未发布数据的 `getDataLayerData`。BLOCK 可见层确实不存在时按原生规则取零；SKY 缺层仍调用原生 `getBrightness`，因为它可能继承更高层底面的阴影，也可能返回直射天光。没有可见层读取接口、接口明确不支持或发生链接不兼容时，同样回到原生查询，不把“无法读取”当成“确定没有光”。邻区块和区段状态也被复用，但跨边界的形状遮挡仍调用原生判定。此读取缓存不改变九区块屏障、修订校验或最终原生边界收尾。

`UniformPalettePackMixin` 对原生单值状态/生物群系容器持锁重新证明单值，直接输出原生单项 Palette；混合容器仍用原生编码。它不改变后续写入和网络格式。`RegionBlockStateContainer` 为新替换的全空区段提供相同优化。

`AirRegionLightBatch` 将同一帧的全空或均匀基岩地板区块一起发布光层，只修复整个批次外缘。自然基岩等不规则残留继续走 `ClearedChunkLighting`；只有底部存在障碍时，把纯空气上方折叠成已证明的统一光值。独立工作线程处理不可变光照快照；世界发布、修订检查、原生边界收尾仍由所属队列执行。`ClearedColumnMetadata` 对仅含空气/基岩的结果一次归约同时产生四种高度图及天光源，其余状态仍用原生重建。

`ParallelChunkCompression` 在保存捕获范围内复制不可变 NBT，并行压缩。`ParallelRegionStores` 由原生 IOWorker 邮箱接纳和合并请求，按 region 文件分为独立写入队列：不同文件并行，同一文件保持先后顺序。原生 RegionFile 继续管理扇区、偏移和外部 `.mcc` 文件。尚未完成的写入有单独的读取快照，普通读取和流式扫描都能看到最新内容；后续原生写入和删除也进入该文件的顺序链。文件缓存淘汰不能提前关闭正在写入的文件，停服先排空已派发请求。

VRE 的普通 DEFLATE 数据经非逐写同步的通道写入。一个批次先同步数据及文件长度，再发布一次原生 region 头并同步；旧扇区直到新头持久化才允许重用。普通原生写入与大型 `.mcc` 写入之前先结束该文件待发布批次。不同文件的 flush 并行；VRE 已同步且未再次修改的文件不重复强制同步。压缩完成、派发和写入内存均不等于落盘完成：完成计数仍等待实际 store futures、持久化与发包屏障。

`NativePaletteImage` 为完整选择的混合区段复制紧凑索引，并映射 Palette 项，避免逐格重新编码。原生/未知回调的掩码与保护规则保持不变。只有原生局部 Palette 布局得到确认才使用此路径；全局 Palette、其他容器、局部几何选择保持通用路径。`UniformSectionEncoding` 缓存实际原生 codec 产生的单值 NBT 模板，每次返回独立副本；不改变文件格式。

新区块已证明为空或均匀基岩地板时，`ClearedInitialLighting` 将初始光层交给批量发布与边界修复。仅当前新建对象的瞬时证明可启用，存档标记本身不能启用。原生 INITIALIZE_LIGHT、LIGHT、FULL 生命周期及最终光照标记/票据释放仍在实际光照完成之后执行。

默认不生成方块战利品。原生写入作用域内，还会阻止删除格同步产生的新物品实体，因此箱子的 `onRemove` 仍完整执行，但不会吐出海量库存。对尚未生成战利品的原生容器，仅在删除作用域的同线程、同世界、同坐标且调用没有显式玩家时跳过 `unpackLootTable`，避免为了丢弃一张藏宝图而同步搜索结构；不清除或改写 loot table、seed 和库存。此作用域不删除已有实体，不影响显式开箱、其他坐标、线程或作用域结束后的正常掉落；Mod 延迟生成的额外掉落需要其宿主适配配合。

## 权限与快照

`canDestroy`、`blocksPropagation` 和区块修改权限分别决定删除、阴影和授权。默认传播为 `NONE`。开启 `AXIS_6`、`AXIS_26` 或 `RAYCAST_REFINED` 后，先只读捕获全范围的阻挡事实；删除尚未开始。静态标签负责阻挡判定，原生修订号和持续的变更订阅验证捕获期间没有混入不同时间的区块状态。

宏体素边长支持 4、8、16。相邻盒只有几何并集不扩大、且传播方向条件允许时才合并，不能为了减少盒数改变阴影定义。源盒、数字修订号和策略信息以独立不可变文件持久化，然后在一个有界后台工作线程中建立索引。后台任务不持有可变区块、方块实体或世界对象。

缺少区块、变更跟踪失效、捕获期间修改或单次捕获超出上限会显式暂停；全局额度暂时被其他工作占用时则等待。未知空间不能当成没有阻挡物。冻结后的旧任务恢复读取原文件并验证哈希，不能重新读取已炸空的世界来计算阴影。

同维度中范围相交、且至少一个启用了传播的任务按接受顺序执行。后一个任务在前一个结束并确认全部收尾后才开始捕获；前一个暂停时也保持顺序，用户可以取消它。这样快照对应轮到该任务执行后的稳定世界，不把多次爆炸误称为共享同一批初始快照。纯几何任务仍可共用预算并在不同区块并行推进。

默认 128 MiB 是操作元数据、整区块准备、捕获、排队/运行中的索引任务、已驻留遮挡索引和批量光照任务共用的估计额度。光照在等待屏障之前就按实际世界高度 `H × 5120` 字节预留，其中 `H × 4096` 用于原有求解工作，额外 `H × 1024` 保守覆盖四个邻区块的两种光层副本；例如高度 384 时预留 1.875 MiB。最多同时接纳八个光照任务，仍须通过剩余全局额度检查；额度不足会走真实原生光照路径。取消后台工作不会立即退还仍被线程持有的数据额度。它不是 JVM 总堆限制；Minecraft 区块、NBT 解码和网络缓冲仍各有独立的有界工作窗口。

## 未生成区块

已有存档区块始终通过原生存储读取，不能拿新空区块覆盖。`ClearedGeneration` 只接受原生存储明确无记录、原生新建 EMPTY ProtoChunk、整高度覆盖、领地和边界允许、无传播/物理更新且开启清流体的目标。生成前先选算法，不生成整块地形再逐格删除。

- `destroyBedrock=true`：直接准备空区段。
- 默认保留基岩：平坦生成器保留真实配置层；已识别的原版噪声地表规则只计算基岩上下带的密度与随机梯度，保留密度/含水层孔洞。未知保护生成规则使用普通生成路径。
- 新空地区块的 `operations.exact_new_chunk_biomes=false` 默认在区块中心、生成器海平面附近采样一次原生生物群系并填充整列。它会降低新区块生物群系边界精度并省略地下群系带；设为 `true` 可计算完整 quart 采样。已有区块生物群系始终保留。

后台并行准备私有区段、生物群系和基岩，主线程批量发布，并继续实际原生 INITIALIZE_LIGHT/LIGHT/FULL 流程。标记随区块保存，后续结构装饰不能向已清空区域写回。原生异步读取/生成预取默认 1024 区块，受全局票据和内存窗口约束。内存临时不足等待在途任务释放，不把活动任务暂停后退回昂贵的普通生成。取消/停服时，尚未发布的预取请求返回原生加载失败而非补生成整块地形；之后真实加载可重试。后台数据额度在工作与发布都结束后释放。

已有 FULL 区块如果还有流体/形状后处理或升级数据，先等待真实 BLOCK_TICKING 后处理，再准备清理；状态显示 `POST_PROCESSING_CHUNK`。这个兼容路径可能需要原生邻块依赖。
## 完成、暂停和恢复

每个原生区块保存镜像同时包含地形、操作 UUID、圈数、精确游标和修改修订号。原生写入前记录 pending，成功返回后才推进游标。外部回调失败、重入保存和无法判定的中断不会被当作已经完成。

完成确认分别等待原生光照、实际 terrain/POI store futures、存储同步，以及需要的区块包提交。包的预算按实际序列化字节乘追踪玩家数计算；无人追踪时不用发包。网络提交不等于远程客户端已经渲染或确认收到。

已经写完的区块进入有界收尾队列，随后可以处理下一区块。正在写入和等待收尾的区块共用票据上限，默认全服务器最多 4096 个，可向下配置；收到确认前继续持有区块修改权。保存以最多 1024 个就绪请求组批，前一批磁盘确认未结束时仍可提交后一批。标记完成前必须等全部确认。状态分别提供准备、加载、写入、光照、保存和发包的实际待办计数，不拿半径比例冒充完成百分比。

取消与暂停也要收完此前已经提交的工作。已持久化的取消记录优先于旧 SavedData；完成标记会阻止旧波面重放到新建筑上。没有可验证的同镜像回执时保守暂停，而不是重新发起一次爆炸。实体伤害没有同镜像恢复证据时也不自动重放。

默认共享主线程预算为 40 ms，并根据当前完整 tick 已消耗的时间保留余量。各维度共用预算。它是分帧上限，不保证未知原生回调可抢占。旧配置文件中的 4 ms、64 区块窗口不会被偷偷改写；升级现有服务器时应同步调整预算。

## 性能测量

使用 `MinecraftServer.tickServer` 入口与返回之间的完整时间。原版 `averageTickTime`/`forge tps` 的采样发生在 Forge END 事件之前，会漏算 END 中的区域操作，不能单独用作本引擎的性能结论。

比较时固定种子、生成和加载状态、CPU、堆大小、保护策略、几何和预算。分别记录准备、主线程提交、光照尾部、存档完成、实际包字节与总任务时间。小型后端采样证明的是该路径的成本；加载范围有限的 R2000 样本不能证明整个 R2000 地形已经处理完毕。

`captureStatistics()` 记录实际同步捕获耗时、侧面捕获耗时、复制的可见光层数，以及 BLOCK/SKY 各自的缓存与原生查询次数。读取缓存和 uniform 编码的原生差分通过只证明这些路径的正确性；尚未完成受控对比前，不据此声称整任务吞吐提升。

最终通过的用例和数值以独立的验证记录为准；本文件描述实现契约，不替代运行结果。


## 并行配置

`budget.preparation_threads` 控制独立的离线地形准备线程池；`budget.io_threads` 控制 region 写入线程池和压缩线程池各自的线程数。两项默认取可见逻辑处理器数并限制在 4–16，配置范围为 1–32，重启生效。世界对象的发布与权限检查仍在服务端线程；不能将任意模组世界回调扔到工作线程。队列有全局在途/元数据约束，存储派发达到 4096 个请求后施加背压。

默认发包额度为每 tick 8 MiB。已有配置不会被自动覆盖；保留旧的 4 ms 时间预算或很小的在途窗口，会继续限制速度。线程数超过实际可用 CPU 不保证更快，测量需要同时记录线程数、CPU 亲和性、GC、堆大小及完整 tick 延迟。

新空地形阶段直接依赖原生 EMPTY 读取结果，由一次离线准备提供直到 FEATURES 的完整镜像；不再为每个已省略的中间阶段排队一次主线程 continuation。若读取到已有或部分生成地形，仍交回正常生成调度。


原生光照存储会省略远离非空区段的空气层。批量发布前先完成原生 section-status 工作，只向实际存在的 updating 光层提交数据；对未分配的层撤销本次不需要的排队数据，使用原生零方块光/向上继承天光规则。不向每个空气层无条件排入 DataLayer：这种数据不会被原生消耗，会使后续每次一致性检查重复遍历不断增长的队列。已有结果和初始空区块光照共用这个限制。

地形准备构造私有 `NoiseChunk` 时，对重复出现的不可变噪声记录临时记忆原生 `hashCode` 结果。作用域仅限当前线程的这一次构造，结束后释放，最多 8192 项；原生结构相等比较和图去重保持不变。它没有把结构去重映射替换为身份映射。本轮短测未证明此项单独提高了基岩路径的吞吐，不能把空区块路径的改善归给它。

`ParallelBedrockBatches` 将同一操作中相邻区块的自然基岩计算合成一批，在准备线程池中并行执行多个批次。完整覆盖的内部采用 4×4，靠近几何边界依次缩为 2×2 或单块，避免为小范围任务计算过大的周围区域。每个批次的底部/顶部各构造一个私有噪声网格，保留逐格随机梯度、原生密度及含水层判断；含水层的私有缓存按实际批次边界分配。原生生成器和批次作用域外的缓存边界不受影响。

该缓存只保存当前操作的数学掩码，不加载、不创建、不修改邻区块。各目标仍须经过独立的读取缺失证明和提交权限复查。该批所有结果被接纳后释放缓存条目；每操作最多暂存 128 批，额外掩码内存计入全局预算，计算中的引用直到工作完成才释放。区块镜像准备通过 future 续接，不占着工作线程等待同一池中的子任务。

## 不规则基岩、并发光照与完成窗口

整列清理后仅剩空气和基岩时，`OpenRegionLighting` 在私有缓冲区联合求解相邻列。适配器按最多 16×16 区块分组；缺席成员作为封闭边界，数组仅为实际成员分配。先直接填充无遮挡天光，只对保留基岩所在的高度带传播阴影边缘。初始传播层同为 14，FIFO 的后续亮度单调递减，每个暗格只入队一次。无天光维度直接生成零天光结果；方块光的外部来源仍由发布阶段校正。

不同组可在准备线程池并行。工作线程只读取已移交的基岩掩码；区块修改、修订号判断、原生光层发布和存储仍各归所属线程。发布前跨过各区块自己的原生光照队列，再安装批内结果。批内共同求解过的边缘不重复扫描；批间只检查能改善当前天光的边，以及可能保留旧发光源影响的方块光。此优化只适用于已经证明为空气/基岩的删除结果，不把同一假设套到任意模组材料。

联合计算结果依赖整组捕获的成员，而不只是结果所属区块。分派前即订阅整组修订号变更；任一成员改变都会使整组结果失效。所有成员的工作结果就绪后才整体进入发布校验，检查当前区块实例和捕获修订号；订阅持续到相关结果全部完成。该规则防止计算期间玩家新放置的发光方块被另一成员的旧零方块光结果覆盖。

不规则列按 `65536 + H×256 + B×1536` 字节预留求解空间，`H` 为世界高度，`B` 为按 section 对齐的保留高度带。同一批按相同 `B` 分组，防止一列高顶把其他列的缓冲区放大。空间不足时在地形提交前等待，不因已经提交后分配失败而突然退回大量逐格光照检查。一般回退路径也将一个区块的检查格集合合成一个原生队列任务，保留检查格集合而减少排队开销。

`CompletionWindow` 从 128 个待完成区块开始，根据真正完成光照、存储和发包的区块数调节窗口；长时间没有完成会收缩窗口。读取预取也遵守该窗口。配置中的 4096 是硬上限，不再作为启动时可直接灌满的目标。计数不把数学结果、提交数或仅光照完成当作最终完成。

客户端的 `LevelChunk` 变更不再分发服务端修订号监听器。对 `clearFluids=true`、无物理更新、无遮挡传播的活动整区块操作，已经清理的格暂时拒绝邻区块流体流回；任务结束即释放该限制，普通流体行为恢复。

实现参考了 [Lucis 的区域计算和发布分工](https://github.com/Team-Argentum/Lucis/blob/master/src/main/java/dev/denismasterherobrine/lucis/light/runtime/LucisRuntimeManager.java)以及 [ScalableLux 对相邻区块调度的锁范围](https://github.com/RelativityMC/ScalableLux/blob/ver/26.2.0/src/main/java/ca/spottedleaf/starlight/common/thread/SchedulingUtil.java)。多线程不意味着可以无约束地同时改写相邻区块。本库上述专用内核为独立实现，没有内嵌这两个项目的实现，也没有宣称替换游戏全部光照引擎。

预读不仅申请 `FULL`，也提前推进具有待执行列表的原生生成后处理。每个预读窗口每 tick 最多提升 32 个请求到原生 `BLOCK_TICKING` 生命周期，并确认真实 ticking future 后降回加载票据；执行游标接管时转移当前票据等级。暂停、取消和结束按实际等级释放，不在世界线程等待 future，也不绕开原生升级或保留方块的后处理。完整区块提交顺序仍由中心向外的游标决定。仅预先加载到 `FULL` 的吞吐测试不足以覆盖这个阶段。

无物理更新的整块提交同时处理已变为原生 `FallingBlockEntity` 的地形：当前位置和来源位置都必须在本次选择范围、世界边界和允许的领地内，并重新经过抗爆及保护规则。受保护方块、范围外来源、自定义下落实体和普通物品不因这项清理被删除。这避免砂砾在调色板清除之后重新落地放回地形。原生删除遗留的未使用调色板 ID 也不再阻止纯空气/基岩列的快速证明；只有含糊的调色板才检查实际使用的 ID。

整块替换发包需要完整的光层含义。原生包中“两种 mask 都没有该层”表示不更新客户端，而非清零；服务端释放的方块光层须显式写入空层 mask，省略的天光层须按原生上层首行继承规则补齐。连续空层共享计算结果，避免逐格重算整列。原生区块光照增量原本只发给视距边缘玩家；在整块操作的实际光照工作及短暂收尾期内，影响范围加一圈光照邻域的原生增量改发给全部正在追踪该区块的玩家，并补齐发生变化的空层。仍复用原生每 tick 合并的变更 mask，不为每个删除格新增网络包，也不将全部相邻区块重复发送完整地形。
