## 算法与原生检查

纯算法检查通过：几何 8,429,426 个体素比较、波面 12,672,930 个体素比较、布尔组合 3,504,303 次集合比较、遮挡 741,403 次比较、相邻阴影 20,840,448 个掩码位比较，以及游标恢复、计划、预算和生命周期检查。

原生完整回归 `native-batch11` 的 **66 个 required GameTests 全部通过**，正常关闭并以退出码 0 结束，未使用强制终止；运行期间源码哈希保持不变。覆盖原生方块实体/流体维护、独立区段光照对照、保护、生成条件失效、冻结传播、多个区块的收尾队列、阶段边界、取消/暂停/恢复、实际炸药物品调用，以及保存失败和外部后续修改。

测试夹具为异步队列使用明确的墙钟期限，避免把加速 GameTest 的 1600 ticks 错当成正常服务器的 80 秒。光照对照使用独立静态维度和不重叠测试区域，等待涉及的所有区块准备完成；保存回读既对照同修订号的冻结期望，也逐列检查 NBT 自身的地形与高度图。没有放松亮度、地形、票据或保存断言。前序失败记录保留在本地各自目录，未计为通过。

## 普通专用服务端

使用实际发布 jar 启动标准 Forge BootstrapLauncher，未使用 Loom 开发启动代替生产加载。服务器只绑定本机测试端口、白名单为空，无在线玩家。每个进程限制一个逻辑 CPU、3 GiB 堆；全部并行重负载工作不超过四个逻辑 CPU。

### 密集地形、保存和重启

在普通噪声地形中，预置 48³ 格立方体，包含 110,591 个石头和一个受保护的基岩，覆盖九个区块。提交半径 64、`generate=false`、`clearFluids=true`、传播与物理均为 `NONE` 的操作。

- 第 2 个 tick 开始清理爆心；全部 110,591 个预置石头变为空气，基岩保留。
- 任务进入 `WRITTEN`，包含原地形共修改 232,262 格，使用 10 个整区段批量提交，排除了五个未加载区块。
- 通过原生存储读回九个区块，分别检查方块内容和同一 NBT 镜像中的操作完成回执。
- 完成后在爆心新放金块，正常保存关闭。复制该已停止的测试世界并重启，金块和基岩均保留，其余 110,590 个预置格仍为空气；旧操作仍为 `WRITTEN`。

这验证正常关闭后的持久化和不重放，不能替代断电或强杀进程的全套故障注入。

### R2000 爆心顺序

另一个普通世界只在爆心附近预置 124 个石头和一个基岩，提交半径 2000 的加载范围内清理。第 3 个 tick 开始清理爆心，124 个石头全部清除，基岩保留。观察期间任务持续推进，最后一次状态采样记录修改 657,518 格，随后按预定时间停止测试。

这是有界观察，**不是整个 R2000 球体完成测试**；也没有生成整个半径范围。旧制品在单独保留的基线运行中停在远处未加载区块，附近 124 个石头均未清除。基线与候选的 CPU 亲和性及工作计数配置并非完全一致，因此这里只比较行为，不据此宣称吞吐提升倍数。

## 分帧与计时

默认共享 CPU 预算为 4 ms/tick，随完整服务端 tick 的负载收缩；最多保留八个正在写入或等待收尾的区块。完整区段采用批量写入，边界和不满足安全证明的状态采用原生精确路径。原生回调、序列化和一次区段提交不能在中间抢占，因此 4 ms 是协作目标，不是硬实时上限。

计时直接采样 `MinecraftServer.tickServer` 的入口到返回，包含 Forge END 中的引擎工作。下一 tick 的 END 读取上一 tick 完成值，并检查采样序号。以下为提交后的固定窗口，包含所有服务端工作，不是仅引擎 CPU；密集样本窗口还包含结束后的少量空闲 tick。未计入关闭服务端的保存时间。

| 场景 | 窗口 | 平均 ms | P95 ms | P99 ms | 最大 ms |
|---|---:|---:|---:|---:|---:|
| 密集地形 R64 | 300 ticks | 10.66 | 32.54 | 145.82 | 192.42 |
| 加载范围内 R2000 | 900 ticks | 10.34 | 21.65 | 118.00 | 309.07 |

单核运行仍存在峰值卡顿，不能宣传成每 tick 恒定 4 ms。原生 `forge tps` 不包含 END 的全部工作，因此没有用它冒充这些完整 tick 数据。上述单次测量不是跨硬件性能承诺，也不是重复多次的吞吐基准。
