# 实现取舍与验证边界

## 性能方向

首要优化是减少必须执行的工作，而不是将 billions 个方块对象交给更多线程：

1. Region/Chunk 三态粗筛；父级 INSIDE 可以免除子级重复几何分类。
2. 全 Section 计划使用 ALL 单例，不分配 4096 个坐标。
3. 边界按列输出连续 Y 行段，整数平方根只求候选界并精确修正。
4. 保护区分静态证明与动态检查，UNKNOWN 不猜测。
5. AXIS_6 的冻结阴影使用 BVH，按 Section 查询，避免每个方块遍历所有阻挡盒。
6. 全局资源额度和背压防止并发任务将加载、快照、光照与保存开销相加后击穿服务器。

首版半格定点协议使几何完全由整数表达；如果未来需要任意连续爆心，应扩展协议和独立 oracle，而不是隐式把 double 四舍五入。

`clearFluids` 按用户确认默认开启。开启时不要求额外流体快照，继续使用原空气清除快速路径。关闭时只在快照含流体的区段产生细分目标：纯流体保留，可破坏含水固体留下其流体，受保护固体保持。无流体的快照仍允许整区段计划；缺失流体数据不能视为“无流体”。保留模式需要额外快照存储和含流体区段的规划工作，不能声称在任意世界中零成本。

## 明确暂缓的优化

- Forge 裸替换整个 Section：未完成各种 Mod 回调与世界派生状态的证明。
- 合法空 Chunk 物化、基岩专用生成：未取得生成器和跨 Chunk FEATURES 的充分安全证据。
- 跨任务自动合并：只可在权限、时序、传播和 receipts 语义保持一致时做，不能仅按空间重叠合并。
- 游戏世界 AXIS_6 快照：库内核可用，测试适配目前保持 NONE，避免边删墙边观察造成结果随顺序变化。
- 自动恢复：世界保存是否已经完成不能由任务 SavedData 的游标推断；不明状态先暂停。

## 可重复验证

`./gradlew regression` 包含：

- 几何与独立朴素/BigInteger oracle 对照、负坐标、边界、超大输入、掩码和 Region 遍历。
- 静态与动态保护、冻结阴影、独立领地/实体权限、生成路径。
- 十个任务共用预算、公平轮转、加载与内存背压、线程所有权、失败清理。
- A→B→恢复 A 的多 receipts、取消认领后不复活旧任务、规则/世界 revision 冲突。
- 日志重开、拒绝重复 ID、强制终结、损坏/截断注入、最大 UTF-8 元数据。

`./gradlew geometryBenchmark` 是几何计划 microbenchmark：预热后五轮取中位数，记录 R=64/200/800/2000；小球与朴素 contains 枚举比较同一体素数量。它不读取 Minecraft 世界，不包含 Chunk 生成、磁盘、光照、实体、网络或复杂 Mod 回调成本。因此不能将它换算为整合包爆炸完成时间。

实际 Forge 世界、FTB 领地、方块实体与保存恢复验证单独记录在测试 mod 文档，纯库测试不替代这些验证。完整生产验收应遵循设计文档第 14 节，使用同一世界和同一保护规则作基准。

## 初次几何测量（2026-10-27）

Java 17.0.19，单逻辑 CPU、SerialGC；先预热一轮，再取五轮中位数。爆心 `(0.5,64.5,0.5)`，世界高度 `[-64,320)`，无保护/遮挡。分配量是本线程累计分配字节，不是峰值常驻内存。

| 半径 | 几何计划中位数 | 候选体素数 | 累计分配字节 |
|---|---:|---:|---:|
| 64 | 1.058 ms | 1,097,917 | 52,408 |
| 200 | 6.575 ms | 30,679,121 | 769,536 |
| 800 | 23.813 ms | 752,387,160 | 8,154,152 |
| 2000 | 56.939 ms | 4,805,792,408 | 47,563,232 |

R=64 的朴素逐方块枚举中位数为 1.479 ms，体素计数完全相同。R=2000 处理约 118 万个相交 Section，其中约 116 万个全覆盖 Section 可直接计数，边界才生成行段。这个结果证明几何层不需要逐一枚举 48 亿格；它**没有证明**实际 Minecraft 能在这些时间内清除、生成或保存世界。

这组数字只是此机器的初次微基准，没有作为稳定性能门槛。原始命令、每轮结果和源代码哈希保留在本地 `.local/runs/geometry-benchmark01/`，不打包进发行物。

## 初次原生 Forge 验证（2026-10-27）

Forge 47.3.7 / Minecraft 1.20.1 / Java 17，独立测试世界，3 个 required GameTests 全部通过：球内外精确删除、基岩与末地折跃门 BE 保留、普通箱子 BE 清除、高度图、抗爆回调替换方块后不误删、NaN 抗爆保守保留、收据序列化及取消/恢复防重放。

测试曾发现 Loom 开发运行环境没有加载库，已增加 `forgeRuntimeLibrary` 并保留发行包内嵌库。高度图测试的旧预期漏算了测试结构上方原有水层；隔离测试列后，爆炸前石头顶/高度图为 -51/-50，爆炸后保留基岩顶/高度图为 -54/-53，与独立逐格扫描一致。

随后补充流体清理及 `clearFluids` 开关，最终 **6 个 required GameTests 全部通过**。默认阈值与降低阈值时，开启清理都使水源、流水、岩浆源、流动岩浆和可破坏含水台阶变为空气；关闭时保留原液态方块状态，含水台阶删除后留下水源。两种模式都保留受保护含水方块及范围外流体。任务 NBT、旧格式默认 true、磁盘意图、物品参数和状态显示均通过核对。流体测试使用基岩小隔间并只在测试准备时移除流体 tick，隔离自然流动，验证直接写入语义；生产代码没有清空整区段流体 tick。

加入开关后的纯库完整回归通过：8,429,426 个独立核对体素、76 项规划检查、70 项调度与恢复检查。默认开启及无流体的保留模式均验证继续使用快速路径，缺少流体数据时拒绝保留模式。

本次没有 FTB 实装领地矩阵、客户端渲染验收、硬断电恢复或大规模真实世界吞吐测试；上述 GameTests 不能代替这些项目。全部原始运行结果在本地 `forge-gametest01..06` 分开保留。
